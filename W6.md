## 1. Actuator Saturation and Integrator Windup

### 1.1 The Physical Saturation Mechanism

Linear control models assume that the actuator can deliver any commanded control effort $u(t) \in (-\infty, +\infty)$. In physical systems, every actuator has strict physical saturation limits: $$u(t) = \text{sat}(v(t)) = \begin{cases} u_{\max}, & \text{if } v(t) > u_{\max} \ v(t), & \text{if } u_{\min} \le v(t) \le u_{\max} \ u_{\min}, & \text{if } v(t) < u_{\min} \end{cases}$$ where $v(t)$ is the unconstrained controller output (the sum of $P + I + D$ terms) and $u(t)$ is the actual signal applied to the plant.

```
                     Linear Feedback Loop Broken During Saturation

   r(t)    +    e(t)   +------------+  v(t)  +------------+  u(t)  +-------+   y(t)
   ------->(x)-------->| Controller |------->|  Actuator  |------->| Plant |----+-->
            - ^        | (P + I + D)|        | Saturation |        +-------+    |
              |        +------------+        +------------+                     |
              |                                                                 |
              +-----------------------------------------------------------------+
```

When a large setpoint change or severe external load disturbance occurs, the control output exceeds the actuator's physical limit. Once the actuator saturates at $u_{\max}$ or $u_{\min}$, the feedback loop is effectively broken because the input applied to the plant remains fixed regardless of output variations.

### 1.2 The Windup Consequence

While the actuator is saturated, the tracking error $e(t) = r(t) - y(t)$ remains non-zero because the actuator cannot deliver enough control authority to drive the plant to the setpoint quickly. Nevertheless, the integral component continues integrating the persistent error: $$I(t) = K_i \int_{0}^{t} e(\tau) , d\tau$$ The integral state grows to a very large value (it "winds up").

```
   y(t) ^                                          Commanded Output v(t) (Huge Peak)
        |          Large Settling Overshoot                 ^
  Target|-------------..----------------                    |        . - - - .
        |            /  \                                   |      .'         '.
        |           /    \                               umax|----+-------------+----
        |          /      '-------------                     |    |             |  Actuator
        +---------+---------------------> t                  |    |             |  Saturated
        0         t_cross                                    +----+-------------+-----> t
                                                             0    t_cross       t_unwind
                                                                  <------------->
                                                                    Lag Period
```

- **Delayed Recovery**: When the plant output $y(t)$ finally crosses the setpoint (at time $t_{\text{cross}}$), the error reverses sign ($e(t) < 0$). However, the accumulated integral state is so large that the unconstrained command $v(t)$ remains far above $u_{\max}$.
- **Prolonged Overshoot**: The actuator remains pegged at maximum effort until the negative error has persisted long enough to discharge or "unwind" the accumulated integral state. This produces large transient overshoot, extended settling times, and can induce sustained limit-cycle oscillations.

---

### 1.3 Anti-Windup Strategies

#### Strategy 1: Integrator Back-Calculation (Tracking Anti-Windup)

Integrator back-calculation dynamically modifies the integrator state equation whenever the actuator saturates.

```
                                  v(t)  +------------+  u(t)
                     ...-(+)----------->|  Actuator  |----+----> Plant
                          ^             | Saturation |    |
                          |             +------------+    |
                          |                   |           |
                          |                   v -         v +
                          |                 +---------------+
                          |                 |   Error es    | = u(t) - v(t)
                          |                 +---------------+
                          |                         |
                          |                         v
                          |                  [ Gain kt = 1/Taw ]
                          |                         |
                          |                         v -
     e(t)        +        |   d/dt(I)      +----+   |
     ----------->(+)------+--------------->|1/s |---+
                  ^                        +----+
                  | Integral State Accumulator
```

1. **Saturation Error Calculation**: The saturation error $e_s(t)$ is measured as the difference between the actual saturated actuator output and the unconstrained command: $$e_s(t) = u(t) - v(t)$$
    - Under linear operation (no saturation), $u(t) = v(t) \implies e_s(t) = 0$, and the controller operates normally.
    - During positive saturation, $u(t) = u_{\max}$ while $v(t) > u_{\max}$, making $e_s(t) < 0$.
2. **Modified Integrator Differential Equation**: The saturation error is fed back to the integrator input scaled by an anti-windup tracking gain $k_t = \frac{1}{T_{aw}}$: $$\frac{d I_{\text{state}}(t)}{dt} = e(t) + k_t [u(t) - v(t)] = e(t) + \frac{1}{T_{aw}} e_s(t)$$ where $T_{aw}$ is the anti-windup tracking time constant.
3. **Dynamic Bleed-off**: When saturation occurs, the negative feedback term $k_t e_s(t)$ actively opposes error accumulation, discharging the integrator state to keep the unconstrained command $v(t)$ close to the saturation boundary. As soon as the error changes sign, the controller immediately comes out of saturation without delay.
4. **Tuning $k_t$ / $T_{aw}$**: A common design rule is to choose $k_t$ larger than $\frac{K_i}{K_p}$ (or set $T_{aw}$ proportional to the integral time constant $T_i$), providing rapid discharge without amplifying high-frequency measurement noise.

#### Strategy 2: Conditional Integration (Integrator Freezing)

Conditional integration stops accumulating error when saturation occurs: $$\frac{d I_{\text{state}}(t)}{dt} = \begin{cases} 0, & \text{if } |u(t)| \ge u_{\max} \text{ and } \text{sign}(e(t)) = \text{sign}(u(t)) \ e(t), & \text{otherwise} \end{cases}$$ If the actuator is saturated and the current error would drive it deeper into saturation, integration is frozen. Integration resumes only when the error reverses sign or the control command falls back within the linear operating range.

#### Strategy 3: Integrator Clamping

The integrator state is bounded mathematically between static upper and lower thresholds: $$I_{\min} \le I_{\text{state}}(t) \le I_{\max}$$ This limits total integral windup but does not adapt dynamically to varying load conditions.

## 2. Derivative Filtering: Eliminating High-Frequency Noise Amplification

### 2.1 The Two Practical Problems of Pure Differentiation

The continuous-time ideal derivative term is given by: $$u_d(t) = K_d \frac{de(t)}{dt} \iff C_d(s) = K_d s$$ This ideal representation presents two major implementation problems:

1. **Unbounded High-Frequency Gain**: The transfer function $C_d(s) = K_d s$ is mathematically improper (numerator degree exceeds denominator degree). In the frequency domain ($s = j\omega$): $$|C_d(j\omega)| = |K_d j\omega| = K_d \omega \xrightarrow{\omega \to \infty} \infty$$ High-frequency electronic measurement noise $w(t)$ from sensors enters the controller. Because differentiation scales with frequency $\omega$, high-frequency noise is heavily amplified. This produces large variations in the control command $u(t)$, causing actuator chatter, mechanical wear, and premature saturation.
2. **Improper Impulse Response (Setpoint Kick)**: An instantaneous step change in reference $r(t)$ produces a discontinuity in tracking error $e(t)$. Differentiating a step discontinuity yields a Dirac delta impulse ($\delta(t)$), demanding an infinite control spike that drives the actuator into immediate saturation.

```
   Magnitude |Cd(jω)| ^
                      |                         / Pure Unfiltered Derivative (Slope: +20 dB/dec)
                      |                        /
                      |                       /
                Kd*N -+----------------------+---------------- Practical Filtered Derivative
                      |                     /                  Rolls off to constant gain Kd*N
                      |                    /
                      |                   /
                  1.0 +------------------+
                      |                  |
                      +------------------+-------------------> Frequency ω (log scale)
                                      ω_cutoff = 1/Tf = N/Td
```

---

### 2.2 First-Order Low-Pass Derivative Filter Formulation

To make the differentiator physically realizable and attenuate high-frequency noise, a first-order low-pass filter pole is cascaded with the derivative term: $$C_d(s) = \frac{K_d s}{1 + s T_f} = \frac{K_d s}{1 + s \frac{T_d}{N}} = \frac{K_d N s}{s + N/T_d}$$ where:

- $T_d = \frac{K_d}{K_p}$ is the derivative time constant.
- $T_f$ is the filter time constant.
- $N$ is the derivative filter factor.

#### High-Frequency and Low-Frequency Limits

- **Low Frequencies ($\omega \ll \frac{1}{T_f}$)**: $$1 + j\omega T_f \approx 1 \implies C_d(j\omega) \approx K_d j\omega$$ The controller acts as an ideal differentiator, providing predictive phase lead and damping transients.
- **High Frequencies ($\omega \gg \frac{1}{T_f}$)**: $$C_d(j\omega) \approx \frac{K_d j\omega}{j\omega T_f} = \frac{K_d}{T_f} = K_d \frac{N}{T_d} = K_p N$$ The gain is capped at $K_p N$, providing high-frequency roll-off that limits noise transmission to the actuator.

#### Practical Tuning Guidelines for $N$

- In industrial practice, **$N$ is typically chosen between 5 and 20** (with $N = 10$ serving as a common starting point).
- Setting $N = 10$ places the filter pole ten times higher in frequency than the zero introduced by the derivative term. This attenuates sensor noise while preserving phase lead near the gain crossover frequency.
- Choosing $N$ too small (e.g., $N < 2$) introduces phase lag at lower frequencies, reducing the damping benefit of derivative action. Conversely, setting $N$ too large (e.g., $N > 50$) allows excessive high-frequency noise to reach the actuator.

## 3. Setpoint Weighting & Two-Degree-of-Freedom (2-DOF) Control

### 3.1 The Setpoint Kick Problem

In standard unity-feedback architectures, all three control terms operate on the error signal $e(t) = r(t) - y(t)$: $$u(t) = K_p [r(t) - y(t)] + K_i \int [r(\tau) - y(\tau)] , d\tau + K_d \left[ \frac{dr(t)}{dt} - \frac{dy(t)}{dt} \right]$$ While external load disturbances $v(t)$ enter smoothly through physical plant dynamics, setpoint changes $r(t)$ are often abrupt steps commanded by operators.

- The derivative term acts on $\frac{dr}{dt}$, generating an impulsive spike in the control signal.
- The proportional term immediately jumps by $K_p \Delta r$, which can cause large overshoot in underdamped systems.

---

### 3.2 Two-Degree-of-Freedom PID Architecture

To mitigate setpoint kick, the reference signal is weighted using two parameters, $\beta$ and $\gamma$: $$u(t) = K_p [\beta r(t) - y(t)] + K_i \int_{0}^{t} [r(\tau) - y(\tau)] , d\tau + K_d \left[ \gamma \frac{dr(t)}{dt} - \frac{dy(t)}{dt} \right]$$ where:

- $\beta \in$ is the **proportional setpoint weight**.
- $\gamma \in$ is the **derivative setpoint weight**.

```
                               Two-Degree-of-Freedom PID Architecture

             r(t)  +-------+
       +---------->|   β   |-------(+)
       |           +-------+        ^
       |                            | - y(t)
       |           +-------+        |
       |  dr/dt    |   γ   |--(+)   |          +-------+
       +---[s]---->|       |   |    +--------->|  Kp   |-------(+)
       |           +-------+   |               +-------+        ^
       |                       | - dy/dt                        |
       |                       v                                |
       |                   [  Kd  ]----------------------------(+)
       |                                                        |
       |                                                        |
       |     r(t)       +  e(t)  +-------+                      |
       +--------------->(x)----->| Ki / s|--------------------->(+)---> u(t)
                         - ^     +-------+
                           |
             y(t) ---------+
```

#### Operational Configurations

1. **Derivative on Measurement Only ($\gamma = 0$)**: Setting $\gamma = 0$ completely removes the reference derivative term: $$u_d(t) = -K_d \frac{dy(t)}{dt}$$ Because the plant output $y(t)$ is physically continuous and cannot jump instantaneously, $\frac{dy}{dt}$ remains finite during step setpoint changes. This eliminates setpoint kick while preserving the dynamic damping needed to attenuate load disturbances.
2. **Softened Proportional Action ($0 \le \beta < 1$)**: Setting $\beta < 1$ reduces the immediate proportional step response to setpoint changes, lowering peak overshoot. In the extreme case $\beta = 0$, proportional action operates purely on negative output feedback ($-K_p y(t)$), producing a slower, well-damped transition to new setpoints.
3. **Preservation of Integral Action**: The integral term **must continue to integrate the unweighted error** $r(t) - y(t)$ to ensure that steady-state tracking error is driven to zero: $$e_{ss} = \lim_{t \to \infty} [r(t) - y(t)] = 0$$ Modifying the integral path would reintroduce steady-state offset.

#### Decoupled Reference Tracking vs. Disturbance Rejection

In this 2-DOF formulation, the closed-loop transfer functions for disturbance rejection and reference tracking are decoupled: $$Y(s) = G_{yr}(s) R(s) + G_{yv}(s) V(s)$$ $$G_{yv}(s) = \frac{P(s)}{1 + P(s)C(s)}, \qquad G_{yr}(s) = \frac{P(s) C_{\text{ref}}(s)}{1 + P(s)C(s)}$$

- The denominator $1 + P(s)C(s)$ dictates closed-loop stability, pole locations, and disturbance rejection, which remain unaffected by $\beta$ and $\gamma$.
- The reference weights $\beta$ and $\gamma$ appear only in the numerator zeros of $G_{yr}(s)$, allowing the transient tracking response to be adjusted without degrading disturbance rejection or stability margins.

## 4. Discrete-Time Implementation & Controller Discretization (Emulation Design)

Most modern industrial PID controllers are implemented on digital processors (microcontrollers, DSPs, or PLCs) executing discrete algorithms at fixed sampling intervals $T$.

```
                         Digital Implementation Control Loop

        r[k]     +   e[k]    +----------------------+  u[k]    +-------+  u(t)
        -------->(x)-------->| Digital PID Algorithm|--------->|  ZOH  |-----> Physical
                  - ^        | (Difference Equation)|          +-------+       Plant
                    |        +----------------------+              |
                    |                   ^                          |
                    |                   | Fixed Clock Interrupt    |
                    |               [ Timer T ]                    |
                    |                                              |
                    |        +----------------------+              |
                    +--------|   A/D Converter      |<-------------+ y(t)
                             | (Sampled Output y[k])|
                             +----------------------+
```

### 4.1 The Emulation Design Methodology

1. **Continuous Design**: Synthesize and tune the continuous-time controller $C(s)$ to satisfy transient and steady-state requirements.
2. **Select Sampling Interval $T$**: Choose a sampling rate fast enough to minimize discretization errors and phase delay.
3. **Discretize**: Map $C(s)$ to an equivalent pulse transfer function $C(z)$ using an algebraic numerical approximation.
4. **Derive Difference Equation**: Convert $C(z)$ into a causal, recursive difference equation relating current output $u[k]$ to past outputs and error samples.
5. **Verify via Simulation**: Test the closed-loop discrete system to ensure that sampling delays have not degraded stability margins.

---

### 4.2 Selection of Sampling Period ($T$)

- **Rise-Time Rule-of-Thumb**: The sampling period $T$ should be chosen to obtain **at least 6 to 10 samples across the system rise time $T_r$** (or dominant time constant $\tau$): $$T \le \frac{T_r}{10} \quad \text{to} \quad \frac{T_r}{6}$$
- **Bandwidth Rule-of-Thumb**: The sampling frequency $\omega_s = \frac{2\pi}{T}$ should be at least **10 to 20 times the closed-loop gain crossover bandwidth $\omega_b$**: $$\omega_s \ge 10,\omega_b \implies T \le \frac{2\pi}{10,\omega_b}$$
- **The Sampling Trade-off**:
    - _Sampling too slowly (large $T$)_: Introduces phase lag (approximated by an effective transport delay $T_d \approx T/2$ from zero-order hold reconstruction), which reduces phase margin and can cause instability.
    - _Sampling too quickly (very small $T$)_: Increases computational burden, requires high-precision floating-point arithmetic to avoid numerical rounding issues, and amplifies high-frequency sensor noise.

---

### 4.3 Continuous-to-Discrete Approximation Methods

#### Method 1: Forward Euler (Forward Difference)

Approximates the continuous derivative via a forward difference: $$s \approx \frac{z - 1}{T} \iff \frac{1}{s} \approx \frac{T}{z - 1}$$

- _Stability Mapping_: Maps the stable continuous left-half $s$-plane into a shifted region $\text{Re}(z) < 1$.
- _Limitation_: Continuous-time stable poles can map outside the unit circle on the $z$-plane if $T$ is not sufficiently small, making this method prone to instability.

#### Method 2: Backward Euler (Backward Difference)

Approximates the derivative via a backward difference: $$s \approx \frac{z - 1}{T z} = \frac{1 - z^{-1}}{T} \iff \frac{1}{s} \approx \frac{T z}{z - 1} = \frac{T}{1 - z^{-1}}$$

- _Stability Mapping_: Maps the entire continuous left-half $s$-plane inside a circle of radius $0.5$ centered at $z = 0.5$ within the unit circle.
- _Properties_: Inherently stable; every stable continuous-time pole maps to a stable discrete-time pole inside the unit circle.

#### Method 3: Bilinear (Tustin) Transform (Trapezoidal Approximation)

Approximates integration using the trapezoidal rule: $$s \approx \frac{2}{T} \left( \frac{z - 1}{z + 1} \right) \iff \frac{1}{s} \approx \frac{T}{2} \left( \frac{z + 1}{z - 1} \right)$$

- _Stability Mapping_: **Maps the entire open left-half $s$-plane directly into the interior of the discrete unit circle** ($|z| < 1$).
- _Frequency Preservation_: A stable continuous-time controller is guaranteed to produce a stable digital controller.
- _Industrial Standard_: Recommended for high-performance controller discretization due to its balance of stability preservation and accuracy.

---

### 4.4 Worked Discretization Example: PI Controller via Bilinear Transform

Consider a continuous PI controller designed for velocity control: $$C(s) = 2 + \frac{5}{s} = \frac{2s + 5}{s}$$ **Task**: Discretize this controller using the Bilinear (Tustin) transform with a sampling period of $T = 0.1\text{ s}$, and derive the executable difference equation.

#### Step 1: Substitute the Tustin Operator

Using $T = 0.1\text{ s}$: $$s \approx \frac{2}{0.1} \left( \frac{z - 1}{z + 1} \right) = 20 \left( \frac{z - 1}{z + 1} \right)$$

Substitute into $C(s)$: $$C(z) = 2 + \frac{5}{20 \left( \frac{z - 1}{z + 1} \right)} = 2 + \frac{5(z + 1)}{20(z - 1)} = 2 + \frac{z + 1}{4(z - 1)}$$

#### Step 2: Combine and Simplify

Express over a common denominator: $$C(z) = \frac{8(z - 1) + (z + 1)}{4(z - 1)} = \frac{8z - 8 + z + 1}{4(z - 1)} = \frac{9z - 7}{4(z - 1)} = \frac{2.25z - 1.75}{z - 1}$$

Factoring in terms of negative powers of $z$ (backward delay operators $z^{-1}$): $$C(z) = \frac{U(z)}{E(z)} = \frac{2.25 - 1.75 z^{-1}}{1 - z^{-1}}$$

#### Step 3: Transform to the Discrete-Time Domain

Cross-multiply to formulate the algebraic relationship: $$U(z) (1 - z^{-1}) = E(z) (2.25 - 1.75 z^{-1})$$ $$U(z) - z^{-1} U(z) = 2.25 E(z) - 1.75 z^{-1} E(z)$$

Taking the inverse $Z$-transform (where $z^{-1} X(z) \iff x[k-1]$): $$u[k] - u[k - 1] = 2.25 e[k] - 1.75 e[k - 1]$$

Rearranging into recursive update form: $$u[k] = u[k - 1] + 2.25 e[k] - 1.75 e[k - 1]$$ This recursive difference equation can be executed directly within an embedded interrupt service routine every $0.1\text{ s}$.

## 5. Practical Software Implementation & Embedded Architecture

When implementing a complete PID controller in software, the algorithm must incorporate **anti-windup**, **derivative filtering**, **setpoint weighting**, and an **execution sequence that minimizes latency**.

```
           Real-Time Execution Loop (Timer Interrupt at Period h)

                     [ Timer Interrupt Triggers ]
                                  |
                                  v
                   1. Read ADC: Sample r[k], y[k]
                                  |
                                  v
                   2. Compute Control Command u[k]:
                      - Proportional: P = Kp * (β*r - y)
                      - Derivative:   D = ad*D_prev - bd*(y - y_prev)
                      - Temp Output:  v = P + I_state + D
                      - Bound Output: u = sat(v, u_min, u_max)
                                  |
                                  v
                   3. Write DAC: Transmit u[k] to Actuator Immediately
                      ==================================================
                      (Minimizes computational input-to-output latency)
                      ==================================================
                                  |
                                  v
                   4. Background State Updates:
                      - Anti-Windup Tracking: es = u - v
                      - Update Integral: I_state = I_state + bi*(r - y) + br*es
                      - Update History:  y_prev = y
                                  |
                                  v
                   5. Sleep until Next Timer Interrupt
```

### 5.1 Precomputed Difference Equations

To minimize execution time within the interrupt service routine, constant coefficients are precomputed prior to loop execution:

- $b_i = K_i h$ (where $h$ is the sampling interval $T$).
- $a_d = \frac{T_f}{T_f + h}$ and $b_d = \frac{K_d}{T_f + h}$ (from backward difference on the filtered derivative).
- $b_r = \frac{h}{T_{aw}}$ (anti-windup reset coefficient).

### 5.2 Latency Minimization Architecture

A common design flaw in digital control loops is performing all background state updates before writing the output to the digital-to-analog converter (DAC).

- **Best-Practice Sequence**: Read the analog-to-digital converter (ADC), evaluate the minimal algebraic operations needed for $u[k]$, and **immediately send $u[k]$ to the DAC**.
- Background tasks—such as updating integral states with anti-windup terms, storing historical values $y_{\text{prev}}$, and logging telemetry—are computed after the actuator signal has been transmitted. This minimizes computational phase lag in the feedback loop.
